# invoice-pdf-hub

[한국어](./README.md) | [日本語](./README.ja.md)

> ブラウザ上で請求書PDFをプレビュー・編集・保存できるWebアプリ。ダウンロード→編集→再アップロードのサイクルをなくすことが目的。

## 背景

インターンとして学んでいる中で、送り状のPDFファイルを扱う過程が複雑で、簡単に作りたいと思いました

1. 請求書PDFをシステムにアップロード
2. 修正が必要な場合、ファイルをダウンロード
3. ローカルで修正
4. 修正版を再アップロード
5. 次の担当者が確認・修正する場合も2〜4を繰り返す

このダウンロード→修正→再アップロードの流れをなくし、**ブラウザ上でプレビューから修正、保存まで完結できるシステム**を作ることがこのプロジェクトの目標です。

## 主な機能

- [ ] **最近のファイルプレビュー(最大10件)** — 最近アップロード・更新されたファイル一覧をサムネイル付きで表示
- [ ] **ダウンロード不要のプレビュー** — 現在アップロードされているファイルをダウンロードせずにブラウザ上で確認
- [ ] **ブラウザ内での編集・保存(ストレッチゴール)** — プレビュー画面でそのまま内容を修正・保存すると、修正後のファイルが最終版としてDB/ストレージに反映

## AI活用について

主要機能(プレビュー・編集・保存)はAIなしで標準的なWeb開発技術とPDF処理技術で実装可能です。ただし余裕があれば、以下のような**任意のAI機能**を追加する予定です。

- OCR + LLMを用いて請求書内のフィールド(商品名、数量、金額、配送先など)を自動抽出
- 抽出したデータをフォームに自動入力
- 異常値(例:金額が0円、配送先の形式が不正など)を自動検知

## アーキテクチャ

```
ブラウザ (Django Template)
     │  アップロード / 参照 / 編集リクエスト
     ▼
APIサーバー (Django)
     │
     ├──▶ メタデータDB (ファイル情報、バージョン履歴)
     ├──▶ ファイルストレージ (PDF原本およびバージョン別ファイル)
     └──▶ (任意) AI抽出サービス — OCR + LLM
```

- ファイル自体はDBではなく別のストレージに保存し、DBにはメタデータ(ファイル名、バージョン、アップロード者、更新日時、パス)のみを保存
- 修正のたびに既存ファイルを上書きせず新しいバージョンとして保存 → 誰がいつ修正したか履歴を追跡可能

## 開発ロードマップ

1. **MVP**: ファイルアップロード + 最近の10件リスト + ブラウザ内プレビュー
2. バージョン履歴機能の追加(誰がいつ修正したかを記録)
3. ブラウザ内編集機能(PyMuPDFのredaction機能でフィールドの位置を検索し、テキストを置換して新バージョンとして保存)
4. (任意) AIによるフィールド自動抽出機能の追加

## 編集機能の実装方針

PDFはWord文書のように構造化されたテキストではないため、自由なテキスト編集よりも**決まったフィールド(配送先、数量など)の値を検索して置換する方式**で実装します。

```python
doc = fitz.open(file_path)
page = doc[0]
rect = page.search_for("既存のテキスト")[0]
page.add_redact_annot(rect)
page.apply_redactions()
page.insert_text(rect.tl, "新しいテキスト", fontsize=10)
doc.save(new_version_path)
```

請求書のフォーマットが毎回同じレイアウトであれば、フィールドの座標を比較的固定的に指定できるため、安定して動作すると想定しています。
